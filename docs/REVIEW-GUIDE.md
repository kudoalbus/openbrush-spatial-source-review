# Developer review entry

OpenBrush Spatial is an independent PICO and Apple Vision Pro experiment in editing spatial strokes while preserving their identity and source samples. Open Brush, Tilt Brush and Toolkit work informed its brush parameters, geometry, formats and behavior. This guide links implementations and tests for maintainers evaluating possible upstream ideas. ## PICO-specific reading

The [engineering handoff](ENGINEERING.md) explains Kotlin/Android source integration and the JVM review selection. There are 78 production Kotlin files and 19 test classes. The Gradle build selects 44 portable production files and resolves JSON-java plus JUnit for the desktop suite. Run `gradle clean test` from the repository root with JDK 17 and Gradle 8.13. The checked-in [build definition](../build.gradle) selects source sets explicitly.

[GlbResources.kt](../pico/app/src/main/java/com/openbrush/picoviewer/data/GlbResources.kt) uses local companion-image callbacks before a known brush fallback. It checks relative resource paths, appends supported image data and preserves the embedded geometry buffer. [GlbResourceTest.kt](../pico/app/src/test/java/com/openbrush/picoviewer/GlbResourceTest.kt) covers custom overrides, nested encoded paths and rejection of escaping/remote URIs using synthetic fixtures. This logic could be evaluated for an upstream importer through host file callbacks.

[StudioRuntime.kt](../pico/app/src/main/java/com/openbrush/picoviewer/ui/studio/StudioRuntime.kt), [StrokeRenderer.kt](../pico/app/src/main/java/com/openbrush/picoviewer/ui/studio/StrokeRenderer.kt) and [ArtworkView.kt](../pico/app/src/main/java/com/openbrush/picoviewer/ui/viewer/components/ArtworkView.kt) show SDK-facing drawing, scene and viewer integration. The desktop suite exercises its selected algorithms. The review edition has no standalone APK build, and this Mac round provides no PICO device acceptance. Keep the recorded Windows 119-test result separate from the [current-round results](STRUCTURE-REVIEW.md#validation-and-publication-status).

## visionOS-specific reading

The [native build instructions](../visionos/README.md) and [technical handoff](VISIONOS.md) cover SwiftUI windows, RealityKit scenes, ARKit hand tracking and optional stylus/audio input. Run `swift test --package-path visionos --scratch-path visionos/.scratch/swift-build` on macOS with Xcode 27.0. The Xcode app has a separate unsigned device-target and simulator build path. Both use included text resources, with source artwork and model dependencies excluded.

[OpenBrushMesh.swift](../visionos/Sources/DrawingCore/OpenBrushMesh.swift), [hull geometry](../visionos/Sources/DrawingCore/OpenBrushHull.swift), [membranes](../visionos/Sources/DrawingCore/OpenBrushMembrane.swift) and [mesh tests](../visionos/Tests/DrawingCoreTests/OpenBrushTests.swift) are useful for evaluating source-arc clipping, UV continuity, pressure profiles and degeneracy handling. [PalmMenuPose.swift](../visionos/Sources/DrawingCore/PalmMenuPose.swift) derives hand-relative menu orientation and palm/back hysteresis, with [pose tests](../visionos/Tests/DrawingCoreTests/PalmMenuPoseTests.swift). These tests establish mathematical behavior. Hand tracking, occlusion and wearer comfort need hardware sessions.

## Integration boundaries for Unity/C#

The interval rules, swept contact, validation invariants and palm-frame calculations can guide a C# implementation. Evaluate their tests against Open Brush's existing stroke storage, brush subdivision and undo commands. Use Unity XR input to supply joints, validity and transforms, and calibrate the thresholds for the actual devices. Bind mesh changes to Unity's brush lifecycle and shader semantics.

The native frameworks own window lifecycle, persistence permissions, rendering materials, collision routing, microphone and accessory input. Kotlin/Android/PICO APIs and SwiftUI/RealityKit/ARKit APIs require separate adapters. Matching a brush GUID or passing geometric tests leaves renderer appearance, blend behavior and timing to be validated. [Platform differences](COMPATIBILITY.md)
