# visionOS technical handoff

## Snapshot and build boundary

The M05 addition starts from source-review commit `1685da52912fd980d269b3d25eaeb7831ef2f193`. Its visionOS source comes from committed development snapshot `cdc7c4a724d284eddb6e64b577a63d0f80c37c98`. The private development history is outside this repository. All 36 runtime Swift files match that snapshot. Four local, uncommitted string-catalog changes were excluded. The review changes are resource packaging, test input and documentation.

`visionos/Sources/DrawingCore` contains platform-independent document, interval, contact and mesh calculations using Apple's Foundation, simd and Compression frameworks. `visionos/App` integrates SwiftUI scenes, RealityKit rendering, ARKit hand input, optional spatial stylus input, microphone analysis and file access. [The Xcode generator](../visionos/scripts/generate-project.py) selects these runtime sources and the included text resources. [Build commands](../visionos/README.md#build-and-test)

The desktop Swift package compiles DrawingCore and its XCTest suite. The native app requires the visionOS SDK. A clean unsigned arm64 Release build passed using Xcode 27.0 (27A266a). The source references SDK 27 APIs and gates relevant runtime features by availability. Its deployment target is visionOS 2.0. Runtime behavior on older supported versions has not been exercised in this review.

## Suggested review sequence

| File | Responsibility and invariants | Unity/C# evaluation |
| --- | --- | --- |
| [StrokeEditing.swift](../visionos/Sources/DrawingCore/StrokeEditing.swift) | `StrokeAppearance.recolor` intersects the requested arc span with visible spans, splits existing overrides, preserves base alpha, removes overrides when restoring the base color and merges compatible neighbors. It keeps source IDs, points and erased spans. `parts` intersects color spans with visible spans using ordered cursors. `DrawingHistory` retains up to 100 whole-document transactions, preserving redo for a no-op. | Port interval algebra and the invariant tests. Connect a gesture transaction to Open Brush history. Evaluate memory and undo granularity against upstream's document model. |
| [SpatialStrokeEdit.swift](../visionos/Sources/DrawingCore/SpatialStrokeEdit.swift) | A tool path sweeps a sphere through the original stroke centerline. AABB bounds reject unaffected strokes. Capsule contact splits the segment by projection into endpoint and cylindrical regions and solves quadratic inequalities. It maps hit parameters back to original cumulative arc lengths. Radius includes the local brush radius. Batches merge contacts before recolor or erase. | The capsule and arc conversion math can be translated to C# vector operations. Calibrate the centerline/radius approximation for each Unity brush family. Selection uses the same contact calculation and visible-span clipping. |
| [DrawingCodec.swift](../visionos/Sources/DrawingCore/DrawingCodec.swift) | Reads v1–v3, writes validated v3 atomically, decodes timestamps directly as Int64 and preserves stroke order. Rejects invalid versions, units, IDs, point arity, nonfinite values, local-color alpha changes and inconsistent intervals. Display placement stays outside the document. | Use the [v3 rules below](#v3-interchange-with-pico) and synthetic fixtures as an optional interchange specification. Preserve canonical TILT behavior in upstream's existing save path. |
| [OpenBrushMesh.swift](../visionos/Sources/DrawingCore/OpenBrushMesh.swift) | Builds ribbon and tube fragments per visible/color span. Computes tangent frames and pressure-dependent widths, maintains arc-relative UVs and supports profile-specific cross sections, taper and wave directions. The associated [surface](../visionos/Sources/DrawingCore/OpenBrushArcSurface.swift), [hull](../visionos/Sources/DrawingCore/OpenBrushHull.swift), [membrane](../visionos/Sources/DrawingCore/OpenBrushMembrane.swift) and [stamp](../visionos/Sources/DrawingCore/OpenBrushStamp.swift) files handle other families. | Evaluate stable source-arc UVs, clipping and geometric degeneracy handling against C# brush implementations. Existing Open Brush algorithms informed these implementations. Swift geometry and RealityKit materials need separate integration work. |
| [PalmMenuPose.swift](../visionos/Sources/DrawingCore/PalmMenuPose.swift) | Uses wrist, middle, index and little-finger joints to derive an orthonormal menu frame. Left/right hand sign corrects the palm normal. Vertical-normal thresholds of ±0.32 select palm/back with the previous face retained between thresholds. Degenerate joint geometry yields no pose. | The basis and face hysteresis can transfer to a Unity hand adapter. Tracking validity, units, handedness and menu placement need hardware calibration. It relies on world-up Y for the palm/back test. |

[SpatialStrokeCapture](../visionos/Sources/DrawingCore/SpatialStrokeCapture.swift) feeds document-local samples into one stroke per pinch. It uses hysteresis, a short engagement delay, motion-dependent smoothing and point spacing. Tracking gaps or large discontinuities end the current capture and require release before another stroke. Hand pressure defaults to 1. Actual pressure is supplied only when available through an input adapter. [Capture tests](../visionos/Tests/DrawingCoreTests/SpatialStrokeCaptureTests.swift)

## Native application integration

[WorkspaceModel](../visionos/App/WorkspaceModel.swift) owns document and history state, save/open tasks and the acceptance replay. [OpenBrushSpatialApp](../visionos/App/OpenBrushSpatialApp.swift) creates the SwiftUI windows, system file controls and mixed immersive space. [SpatialStudio](../visionos/App/SpatialStudio.swift) connects tracked input, tools, history and transforms. [SpatialStudioRenderer](../visionos/App/SpatialStudioRenderer.swift) keeps completed live-preview chunks and rebuilds the active tail where supported. Surface geometry can need broader regeneration. This review includes no performance benchmark.

The [palette](../visionos/App/SpatialPalette.swift) and [brush book](../visionos/App/PicoBrushBook.swift) present native controls using hand-relative transforms. The [renderer](../visionos/App/WorkspaceRenderer.swift), animation helpers and audio input map profiles to RealityKit entities and materials. These Apple APIs and scene lifecycles require host-specific implementations in Unity. The catalog's 102 enabled GUIDs establish identifier and geometry coverage. Material blending, transparency, animated effects and audio response have varying fidelity to the original Unity brushes. Per-brush visual equivalence remains unverified.

## v3 interchange with PICO

The Swift codec and the existing [PICO codec](../pico/app/src/main/java/com/openbrush/picoviewer/data/DrawingDocumentCodec.kt) use the following rules.

| Element | Shared meaning |
| --- | --- |
| Root | `version` is 1, 2 or 3 on read. Swift writes 3. `units` is `meters_rh`. Stroke array order is meaningful. |
| Stroke | Keep `id`, `brush`, `width`, RGBA base `color`, original `points`, `erased` and v3 `recolored`. IDs are nonempty and unique. Brush GUIDs retain their identity through serialization. |
| Control point | V1 has `[x,y,z,pressure,timeMs]` with an implicit `(0,0,1)` normal. V2/v3 has `[x,y,z,pressure,timeMs,nx,ny,nz]`. Time is a nonnegative signed 64-bit integer. Coordinates are document-local, right-handed meters. Normals are finite and nonzero. |
| Erase | `[start,end]` measures cumulative distance along the original stroke. Display derives visible spans without resampling or splitting the stored stroke. Swift preserves imported interval arrays. PICO can merge equivalent erasures, so compare visibility when normalizing redundant input. |
| Recolor | `[start,end,r,g,b,a]` is sorted and nonoverlapping. Alpha equals original base alpha. Recolor acts only on visible intersections. Hidden historical color may remain stored under erasure and stays invisible. |
| Placement | Runtime centering, scale and room/session transforms belong to entities. They do not rewrite saved points or intervals. Persistent room anchoring is outside the JSON schema. |
| Validation | Width is 0.001–0.15 m. Editable documents allow up to 2,000 strokes, 4,096 points per stroke, 200,000 total points and 20,000 erase/color intervals of each kind per stroke. Swift has no extra byte-size cap. The existing PICO reader has its own input-length bound. |

The included [synthetic fixture](../visionos/ReviewResources/workspace-v3.json) has a blue base stroke from 0 to 0.32 m, red at 0.08–0.12 m, a gap at 0.12–0.16 m and green at 0.16–0.20 m. Recoloring 0.10–0.18 m orange changes only 0.10–0.12 and 0.16–0.18 m. Its ID, points, brush, width, base color and erasure stay unchanged. [Tests](../visionos/Tests/DrawingCoreTests/DrawingCoreTests.swift) exercise the gap, no-op history, alpha, precision and save/reopen. [The simulator verifier](../visionos/scripts/verify-interop.py) checks the app-saved result independently.

For a new cross-device exchange, the Mac developer exports a synthetic or user-owned v3 file, the Windows developer reads and exports it through PICO, and the Mac developer compares the returned file with `python3 visionos/scripts/compare-v3.py original.json returned.json`. The comparator checks schema, order, identities and exact integer timestamps, with a 1e-6 tolerance for float values. A fresh device-to-device exchange of this review snapshot remains pending.

## Review resources and limitations

The Xcode project bundles JSON brush descriptions, palette target coordinates, localization text and the synthetic JSON stroke. Brush geometry, rendering and texture-description catalogs are identical to the existing PICO review versions. The visionOS brush-menu order matches its development snapshot. The [manifest](../visionos/REVIEW-MANIFEST.json) identifies copied, modified and review-authored files and records SHA-256 hashes. [The verifier](../visionos/scripts/verify-review.py) checks all selected files and protects the baseline PICO tree and JVM build definitions.

External models, source textures, icon atlases, real TILT artwork, screenshots and signing data are excluded. Model and texture lookup already has fallback paths in the native source. The standalone build passes using the included files. Its appearance and brush-book presentation differ from the full private app, and the bundled TILT example button has no artwork to load. The [resource instructions](../visionos/README.md#resources-and-reproducibility) describe separately cleared or newly authored replacements. Synthetic TILT data is generated in memory by the [test helper](../visionos/Tests/DrawingCoreTests/SyntheticTilt.swift). That input covers a supported stored-ZIP/sketch-v5 path and corruption rejection. Broad real-world TILT compatibility needs independent fixture clearance and testing.

USDZ viewing uses RealityKit's loader. TILT container v1 with sketch v5/v6 maps supported stroke data into editable v3 or preview geometry, with new IDs, coordinate conversion and diagnostics. Groups, external models, room placement, images and complete Unity material fidelity are outside the editable mapping. GLB/glTF is not implemented in this visionOS source. Selected binary Gaussian PLY and 32-byte SPLAT/SPLT layouts are parsed, while native Gaussian rendering requires the relevant visionOS 27 device APIs. Spatial stylus handling requires supported visionOS 26+ accessories and permission. These paths need separate hardware validation.
